# Data Model: Mentor Profile & Teaching Skills Management

The persistence model mirrors existing tables; it does not create or alter them. SQL Server `DATETIME2(3)` values are treated as UTC by repository convention.

## MentorProfile (`dbo.mentor_profiles`)

| Field | SQL type | Mapping / constraint |
|---|---|---|
| userId | BIGINT | Primary key and FK to `users.id` |
| slug | VARCHAR(200) | Required, unique |
| headline | NVARCHAR(250) | Required |
| jobTitle | NVARCHAR(150) | Required |
| companyName | NVARCHAR(200) | Optional |
| biography | NVARCHAR(1000) | Required, trimmed length 50–1000 |
| yearsExperience | DECIMAL(4,1) | Required, range 0–80 |
| experienceSummary | NVARCHAR(MAX) | Optional |
| languageCodes | NVARCHAR(500) | Required JSON array text; defaults to `[]` in SQL |
| isPublic | BIT | Required, defaults false; true requires approval metadata |
| acceptingMentees | BIT | Required, defaults false |
| maxActiveMentees | INT | Required, greater than zero |
| approvedBy | BIGINT | Optional FK to `users.id` |
| approvedAt | DATETIME2(3) | Optional |
| createdAt / updatedAt | DATETIME2(3) | Required, UTC |

`userId` is intentionally a scalar key; no `User` entity is introduced in this scope.

## MentorAccount (`dbo.users`, narrow projection)

| Field | SQL type | Mapping / constraint |
|---|---|---|
| id | BIGINT | Existing users primary key; never generated by this service |
| fullName | NVARCHAR(150) | Required |
| bio | NVARCHAR(1000) | Optional |
| githubUrl | NVARCHAR(500) | Optional |
| linkedinUrl | NVARCHAR(500) | Optional |
| portfolioUrl | NVARCHAR(500) | Optional |
| roleCode | VARCHAR(20) | Existing account role; read-only, `/me` requires `MENTOR` |
| status | VARCHAR(20) | Existing account status; read-only, `/me` requires `ACTIVE` |
| updatedAt | DATETIME2(3) | Required, UTC |

This mapping is intentionally partial and used only to update/read UC10 profile fields and verify the configured demo account is an active mentor. Role and status are internal authorization checks, never writable or returned in profile DTOs. Credentials and unrelated security fields are not mapped.

## Skill (`dbo.skills`)

| Field | SQL type | Mapping / constraint |
|---|---|---|
| id | BIGINT IDENTITY | Primary key |
| categoryId | BIGINT | Required FK to `skill_categories.id` |
| name | NVARCHAR(100) | Required, unique |
| slug | VARCHAR(150) | Required, unique |
| description | NVARCHAR(500) | Optional |
| active | BIT | Required; only true skills appear in mentor skill-tag repository reads |
| createdBy | BIGINT | Optional FK to `users.id` |
| createdAt / updatedAt | DATETIME2(3) | Required, UTC |

Category and creator are scalar IDs because those entities are outside this bounded scope.

## MentorSkill (`dbo.mentor_skills`)

| Field | SQL type | Mapping / constraint |
|---|---|---|
| mentorId | BIGINT | Composite primary key and FK to `mentor_profiles.user_id` |
| skillId | BIGINT | Composite primary key and FK to `skills.id` |
| yearsExperience | DECIMAL(4,1) | Optional, range 0–80 |
| verified | BIT | Required; verified rows require verifier and timestamp |
| verifiedBy | BIGINT | Optional FK to `users.id` |
| verifiedAt | DATETIME2(3) | Optional |
| displayOrder | INT | Required, defaults zero |
| createdAt | DATETIME2(3) | Required, UTC |

The association is modeled as an entity with an embedded `(mentorId, skillId)` key and `@MapsId` relationships to `MentorProfile` and `Skill`. The active-only repository query filters the joined `Skill.active` field; the association itself is retained when a skill becomes inactive.

## DTOs

- `MentorProfileRequest`: validates full name, biography, experience, optional external URLs, and a non-empty list of unique active skill IDs. It cannot set approval or public-visibility metadata.
- `MentorProfileResponse`: safe profile/account values and active mentor skills; does not expose JPA entities, approver identity, or unrelated account data.
- `SkillTagResponse`: skill catalog details needed to present a selectable skill tag.
- `MentorSkillResponse`: link-level experience/verification/order plus safe skill tag details.

## Service offering boundary

`service_offerings` persists price as `MONTHLY` or `ONE_OFF`. Neither SRS UC10 (profile) nor UC11 (teaching skills) specifies editing service offerings; no hourly price property is added to the profile DTO or editor in this feature.
